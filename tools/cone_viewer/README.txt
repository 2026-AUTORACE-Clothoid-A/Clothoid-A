전용 콘 시각화 창 (Qt, Docker)

cone-main-safe-exit 브랜치에서는 콘 내부 분류·주행을 main 방식으로 재계산합니다.
내부 주행은 speed 0.4 / 호장 lookahead 0.4, 탈출은 exit_speed 0.25 / 후축 원 반경 0.35로
분리됩니다. 코너 보완·경계 기억·경로 완화 실험은 내부 주행에 적용하지 않습니다.
정지선/신호등 코드는 stopline-develop을 유지하며, 초록 오검출로 접근 제한이 풀리는
기존 문제는 이번 콘 통합에서 수정하지 않았습니다.

호스트 저장소에서 실행
  python3 tools/cone_viewer/launch.py
  python3 tools/cone_viewer/launch.py bag/cone_latest4_review/bag_1114_050802

Docker 안에서 실행
  source /opt/ros/humble/setup.bash
  cd /home/user/Clothoid-A
  OPENBLAS_NUM_THREADS=1 python3 tools/cone_viewer/viewer.py

기본 목록은 최근 콘 백 4개이며 최신 백부터 표시합니다.
백 선택 / 백 폴더 열기 / 현재 코드로 재계산 버튼으로 다른 백이나 소스 변경을 확인합니다.
Space 재생·정지, 좌우 방향키 1스캔 이동, 슬라이더 시간 이동, 이벤트 클릭 구간 이동.
재생은 끝에서 멈춥니다. 자동 반복하지 않습니다.

왼쪽은 원본 카메라, 가운데는 원본 라이다와 현재 코드의 콘 경계·경로·목표점입니다.
▲ 파랑 왼쪽 경계, ■ 주황 오른쪽 경계, 초록 중심 경로, 분홍 목표점.
출구에서 노란 ×는 마지막 관측 경로 끝점, 초록 ○는 연장 구간을 포함한 끝점입니다.
출구 경로는 현재 ExitPathMemory로 계산하며 차선 준비 신호는 원본 백을 사용합니다.
저장 경로를 이동시키는 위치는 실행 노드와 같은 ConeOdometry로 재계산합니다.
/odom의 전진 속도를 후축에서 적분하고 /imu 자이로로 회전하며, 차체 중심 오프셋을 반영합니다.
IMU가 없는 백에서는 위치 기억 경로를 재현하지 않습니다. 새 주행은 /cone/odom도 기록하면
실행 당시의 로컬 위치와 재계산을 비교할 수 있습니다(cbag /cone/odom).
스캔 단위 재계산이므로 실제 노드의 20 Hz 타이머·콜백 시각과는 차이가 있습니다.
후차축이 관측 끝점의 진행 위치를 통과하면 저속 차선 연결을 시작합니다.
연결 중에는 새로 검출한 /lane/cone_exit_candidate와 IMU/속도 피드백으로 현재 차선의 조향을
연속적으로 이어받은 뒤 종료합니다. 직진, 고정된 출구 방향, 정해진 주행 시간은 요구하지 않습니다.
옛 백에 /lane/cone_exit_candidate가 없으면 후축 도달 뒤 연결 대기로 표시합니다.
차선 명령이나 완료 신호를 추정해서 연결 성공으로 표시하지 않습니다.
새 백은 cbag /cone/odom /cone/connecting /lane/cone_exit_candidate 로 기록합니다.
저장된 관측 끝점이 없으면 차선 준비 신호만으로 종료하지 않고 정지합니다.
기존 백의 차선 준비 신호는 기존 종료 동작에 영향을 받은 기록입니다. 종료 조건 변경 후의
실제 복귀 시점·차량 움직임을 검증하려면 수정 코드로 새로 주행한 백이 필요합니다.
연보라 점선은 현재 조향 명령에 차량 조향 제한을 적용한 자전거 모델 궤적입니다.
이는 실제 주행 결과를 예측하거나 검증한 경로가 아닙니다.
관측 시간이 초과된 경계는 점선으로 표시하며, 전진 경로를 임의로 그리지 않습니다.
상태는 현재 코드로 재계산하며, 기록된 /cmd_vel은 별도로 표시합니다.
순서가 다른 ROS 콜백 스케줄이나 센서 지연은 이 오프라인 재계산과 다를 수 있습니다.
현재 소스는 백을 열거나 재계산 버튼을 누를 때 다시 불러옵니다.
출력 토픽을 발행하지 않고 백 파일을 읽기 전용으로 엽니다.
